In 4G, user data travels in EPS Bearers. Each EPS Bearer connects the UE to the P-GW and has exactly one QoS treatment, identified by its QoS Class Identifier (QCI).

In 5G, user data travels in PDU Sessions, which connect the UE to a data network through the UPF. A single PDU Session can carry several QoS Flows, each with its own QoS treatment, identified by its 5G QoS Identifier (5QI).

That is the core change. 4G ties QoS to the EPS Bearer. 5G separates connectivity, provided by the PDU Session, from QoS treatment, provided by the QoS Flow.

## An EPS Bearer is the unit of QoS in 4G

Each EPS Bearer has its own QoS profile, which determines how its packets are treated. All packets belonging to the same EPS Bearer receive the same QoS treatment.

[3GPP TS 23.401](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=849) defines the EPS Bearer and its role in the Evolved Packet System (EPS).

EPS Bearers live inside a PDN Connection, the connection to a data network identified by an Access Point Name (APN). A PDN Connection has one default EPS Bearer and zero or more dedicated EPS Bearers.

- **Default EPS Bearer:** set up with the PDN Connection and kept for its whole lifetime. Carries traffic with the connection's default QoS treatment.
- **Dedicated EPS Bearer:** added when traffic needs a QoS treatment different from the default, such as voice.

### Each EPS Bearer has corresponding transport resources

3GPP TS 23.401 maps each EPS Bearer to an E-UTRAN Radio Access Bearer (E-RAB). An E-RAB comprises the Data Radio Bearer (DRB) between the UE and the eNodeB and the corresponding S1-U tunnel between the eNodeB and the Serving Gateway (S-GW).

A PDN Connection with two EPS Bearers therefore uses **two DRBs** and **two S1-U tunnels**.

In 4G, each EPS Bearer has corresponding radio and transport resources. Adding a dedicated EPS Bearer introduces a separate bearer context and its associated resources.

That is one of the key differences from the 5G QoS model.

## A PDU Session carries one or more QoS Flows

A Protocol Data Unit (PDU) Session provides user-plane connectivity between the UE and a data network through the User Plane Function (UPF).

The PDU Session is identified by a PDU Session ID. Its data network is identified by a Data Network Name (DNN), which plays a role similar to the APN in 4G.

A UE can establish several PDU Sessions, to the same DNN or to different ones.

[3GPP TS 23.501](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3144) defines the PDU Session as part of the 5G system architecture.

Inside the PDU Session, traffic is separated into QoS Flows. The QoS Flow is the finest granularity of QoS treatment in a PDU Session.

Each QoS Flow has its own QoS parameters, including a 5QI. Every packet on the flow gets the same treatment.

The UE assigns each uplink packet to a QoS Flow using its QoS rules. Each QoS rule associates a set of packet filters with a QoS Flow, and the network provides these rules when it establishes or modifies the PDU Session.

The PDU Session provides the connectivity. The QoS Flows separate the traffic by QoS.

## One GTP-U tunnel on N3 carries every QoS Flow of a PDU Session

In 5G, GTP-U tunnels carry user data between the gNodeB and the UPF over the N3 interface.

In the basic case, the gNodeB and the UPF use one GTP-U tunnel per PDU Session, not one per QoS Flow.

The tunnel is set up with the PDU Session. All QoS Flows of the session share that tunnel.

But if the tunnel is shared, how does the UPF tell the flows apart?

### The TEID identifies the PDU Session

Every GTP-U header carries the 32-bit Tunnel Endpoint Identifier (TEID) of the receiving endpoint, as defined in [3GPP TS 29.281](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=1699).

The receiver uses the TEID to find the PDU Session the packet belongs to.

The TEID says nothing about the QoS Flow. That is the job of the QFI.

### The QFI identifies the QoS Flow

The QoS Flow Identifier (QFI) is a 6-bit value that identifies a QoS Flow within a PDU Session.

On the N3 interface, the QFI is always carried in the PDU Session Container within the GTP-U encapsulation. Over the radio interface, the SDAP layer maps QoS Flows to DRBs. The QFI can also be included in the SDAP header, although its presence there is optional.

Three identifiers, three jobs:

- **TEID:** identifies the tunnel endpoint, and therefore the PDU Session, on N3.
- **QFI:** identifies the QoS Flow within the PDU Session.
- **DRB:** carries user data between the UE and the gNodeB over the radio interface.

Several QoS Flows can share a DRB, or each can get its own. The gNodeB decides.

In other words, the number of QoS Flows does not set the number of GTP-U tunnels on N3 or the number of DRBs.

### Let's follow an uplink packet

Consider the PDU Session in the diagram above, with three QoS Flows.

1. The UE classifies an outgoing packet into a QoS Flow according to its QoS rules.
2. The UE sends the packet over a DRB mapped to that QoS Flow.
3. The gNodeB forwards the packet over N3 using GTP-U encapsulation, including the TEID and QFI identifiers.
4. The UPF identifies the PDU Session using the TEID and the QoS Flow using the QFI.
5. The UPF forwards the packet toward the data network over N6.

The same GTP-U tunnel can carry packets belonging to all three QoS Flows.

The TEID separates PDU Sessions. The QFI separates QoS Flows.
